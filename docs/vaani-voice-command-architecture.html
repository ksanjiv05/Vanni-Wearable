1 · Library choice — why ESP-SR

Goal: a "Hey Vaani"-style always-listening assistant that runs fully on the wearable, offline, no cloud. I evaluated the three viable options for the ESP32-S3. ESP-SR wins decisively because your exact chip (the N16R8) is the hardware Espressif built the framework for.

Why ESP-SR is the right call for Vaani: it is the only option that gives a real "Siri/Alexa" experience — a low-power neural wake word always listening, then a multi-command recognizer — entirely offline, and it was engineered specifically for the ESP32-S3's PSRAM + vector instructions. Your N16R8 already meets its hard requirements, so there's no hardware upgrade needed — only a microphone (and optionally a speaker for audio feedback).

3 · Wiring — INMP441 mic + MAX98357A speaker

The ESP32-S3 has two I2S peripherals, so the mic (I2S-0 RX) and the amplifier/speaker (I2S-1 TX) run on independent buses — no sharing conflicts. All pins below are chosen to avoid the TFT + SD pins already in use and the N16R8's reserved octal-PSRAM pins (GPIO 33–37).

Pin-conflict check (done): GPIO 4, 5, 6, 7, 15, 16 are all free — they don't touch the TFT (10/17/18/12/11/21), the SD card (14/13), the native-USB pins (19/20), or the N16R8's octal-PSRAM pins (33–37). Safe to add without disturbing anything already verified.
The speaker is optional — it only gives audio feedback (a "ding" when the wake word is heard, or spoken replies). If you skip it, wake-word + commands still work fully; the TFT already shows "Listening…" as visual feedback.

4 · Proposed command set (wake word + Vaani actions)

SpokenTypeAction on the wearable
"Hi Vaani" (wake word)WakeNetWakes the recogniser · TFT shows "Listening…" · optional chime
"Start recording"MultiNetBegin capturing mic audio → /vaani/rec-*.wav on SD
"Stop recording"MultiNetClose the WAV file, update pending count
"Sync notes"MultiNetTrigger BLE/Wi-Fi transfer of pending recordings to the app
"How many pending"MultiNetShow/announce the pending-transfer count
"Delete last"MultiNetRemove the most recent recording (with on-screen confirm)
Wake word note: WakeNet ships a set of prebuilt words ("Hi ESP", "Alexa", "Hi Lexin", etc.). A truly custom "Hi Vaani" requires a model trained by Espressif's service — so for v1 we'd pick the closest prebuilt wake word, and the 5 commands above are fully custom via MultiNet (that part is free-form English).

5 · Constraints & build path (read before we start)

Flash / partition
  • Current firmware is at 95% of the default partition.
  • ESP-SR models need a dedicated model partition (several MB).
  • → Requires a custom partition table (16MB gives plenty of room) or a separate "voice" firmware image.
Framework
  • ESP-SR is officially ESP-IDF.
  • arduino-esp32 3.x ships an ESP_SR wrapper, but it's stricter than our current Arduino flow.
  • → Likely move the voice build to ESP-IDF (or IDF-as-component in Arduino).
Compute / memory
  • WakeNet + MultiNet + AFE run in PSRAM on Core 1.
  • N16R8's 8MB PSRAM is sufficient; leaves headroom for SD + BLE.
  • Continuous listening draws more power — fine while worn/charged.
Suggested phasing
  • P1 Mic + I2S capture test (raw audio to serial/SD).
  • P2 WakeNet wake word → TFT "Listening…".
  • P3 MultiNet 5 commands → dispatcher → SD/sync.
  • P4 (opt) MAX98357A chime / spoken feedback.
